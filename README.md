# Parallel PIDC Presentation

Manim-animated presentations authored in [Slidev](https://sli.dev), rendered
with [Manim Community Edition](https://www.manim.community/).

Animations are written as plain Manim `Scene`s and rendered to video with
Manim's native `--save_sections` checkpointing (one clip per
`self.next_section()` call). Slidev owns everything else — slide layout,
text, pacing, and click-by-click navigation. The two toolchains never talk to
each other directly; a build script bridges them by rendering videos and
generating small Vue wrapper components that Slidev picks up automatically.

See [`docs/COMPONENTS.md`](docs/COMPONENTS.md) for how the Manim ↔ Slidev
video bridge actually works, and [`slides/README.md`](slides/README.md) for
Slidev-specific dev commands.

## Project structure

```
.
├── ppidc/                      # Python package: Manim scenes + supporting code
│   ├── cfg.py                  # shared config (colors, resolution, etc.)
│   ├── data.py                 # data prep / helpers feeding the scenes
│   └── slides.py                # Manim Scene subclasses — the actual animations
├── scripts/
│   └── build_assets.py         # renders scenes, syncs videos + components into slides/
├── slides/                     # Slidev project (separate Node/pnpm toolchain)
│   ├── slides.md                # slide content — markdown + component tags
│   ├── components/
│   │   ├── ManimClip.vue        # double-buffered video player, click-synced
│   │   └── generated/           # auto-generated per-scene wrapper components
│   ├── ext/                     # Slidev theme
│   ├── pages/                   # multi-file slide content, if split up
│   ├── public/
│   │   └── videos/              # rendered clips (generated, not hand-edited)
│   └── snippets/                # generated copy-paste reference (generated, not hand-edited)
├── codebook.toml
├── pyproject.toml               # uv-managed Python project (Manim, etc.)
└── uv.lock
```

Directories not hand-authored — `slides/public/videos/`, `slides/snippets/`,
`slides/components/generated/` — are fully regenerated by `build_assets.py`
on every run. Don't edit them directly; edit `ppidc/slides.py` (or add new
scene files under `ppidc/`) and re-run the build.

## Prerequisites

| Tool                             | Used for                                                      | Install                         |
| -------------------------------- | ------------------------------------------------------------- | ------------------------------- |
| [uv](https://docs.astral.sh/uv/) | Python env + dependencies (Manim)                             | see uv docs                     |
| Python 3.10+                     | Manim requires it                                             | installed automatically by `uv` |
| FFmpeg                           | Manim video encoding                                          | must be on `PATH`               |
| LaTeX (e.g. MiKTeX/TeX Live)     | some scenes use `MathTex`/`Tex`                               | see Manim's install docs        |
| Node.js 18+                      | Slidev / Vite                                                 | official installer or nvm       |
| pnpm                             | Slidev's package manager (this project uses `pnpm-lock.yaml`) | `npm i -g pnpm`                 |

> **Windows note:** everything above works natively on Windows — no WSL
> required. The one thing to watch is Manim's own dependency chain
> (MiKTeX, FFmpeg on `PATH`) tends to have more setup friction there than
> on macOS/Linux. `build_assets.py` itself is Windows-safe (it copies
> files rather than symlinking, and forces UTF-8 for all output).

## Setup

```bash
# Python side
uv sync

# Slidev side
cd slides
pnpm install
cd ..
```

## Build workflow


**1. Render Manim scenes and sync everything into `slides/`:**

```bash
uv run python scripts/build_assets.py
```

This discovers every `Scene` subclass under `ppidc/`, renders each with
`--save_sections`, and:

- copies clips into `slides/public/videos/<scene-slug>/`
- writes `slides/public/videos/manifest.json` (all scenes → clip URLs)
- writes a per-scene wrapper component to `slides/components/generated/`
  (e.g. `<TransposeTransform />`) so `slides.md` never has to reference raw
  clip paths
- writes `slides/snippets/` — copy-paste reference for each scene, showing
  the one-line component tag plus the exact `clicks:` frontmatter value
  needed (see `docs/COMPONENTS.md` for why that number can't be
  auto-inserted)

Useful flags for `scripts/build_assets.py`:

```bash
uv run python scripts/build_assets.py --quality h        # 1080p60 (default: -ql, fast preview)
uv run python scripts/build_assets.py --scene slides.Intro  # render just one scene
uv run python scripts/build_assets.py --clean             # wipe slides/public/videos/ first
```

For testing purposes, individual manim-animated scenes can be built. 
The following is an example of building `TransposeTransform` scene using `manim`.

```sh
uv run manim -pql ppidc/slides.py TransposeTransform
```

**2. Author/preview the deck:**

```bash
cd slides
pnpm dev
```

Opens the deck at `http://localhost:3030` with hot reload. Check
`slides/snippets/SNIPPETS.md` for the exact tag + `clicks:` value to paste
for each scene — this file only exists after step 1 has been run at least once. 


**3. Build the static site:**

```bash
cd slides
pnpm build
```

Outputs a static SPA to `slides/dist/` — servable from any static HTTP
server (nginx, Netlify, Vercel, GitHub Pages, `pnpm preview` locally, etc.),
as long as the server does SPA fallback routing (unknown paths → serve
`index.html`) and, if hosted under a subpath, `--base` is set to match.

## Fast edit-build-view loops

For rapid iteration, use the watcher scripts instead of running the build commands manually.

### Animation-only loop

Best for iterating on the animation itself. Watches `ppidc/*.py` and re-renders a single scene with `manim -ql` on every save.

```bash
uv run --group dev python scripts/watch_scene.py TransposeTransform
```

Keep a browser or video player open on the printed output file and refresh it after each render. The `-p` flag is intentionally omitted so the watcher does not spawn a new video player window on every save.

For example, with `mpv` you can loop the output file so it automatically reloads the new render when the watcher finishes:

```bash
mpv --loop-file=inf media/videos/ppidc/slides/TransposeTransform.mp4
```

`watch_scene.py` prints the exact video path after each render. Save the source file, and `mpv` will pick up the updated clip on the next loop.

### Full slide loop

Best for checking pacing and click-sync inside the actual deck. Watches `ppidc/*.py` and re-runs `build_assets.py`, while `pnpm dev` hot-reloads the deck.

```bash
# terminal 1
uv run --group dev python scripts/watch_assets.py

# terminal 2
cd slides
pnpm dev
```

Then open `http://localhost:3030`.

## Adding a new animated slide

1. Add a `Scene` subclass to `ppidc/` (new file or append to `slides.py`),
   using `self.next_section("label")` at each pause point.
2. `uv run python scripts/build_assets.py`  
   (while iterating, use `uv run --group dev python scripts/watch_assets.py` instead)
3. Open `slides/snippets/<slug>.md`, copy the `clicks:` value and component
   tag it prints into the right spot in `slides/slides.md`.
4. `cd slides && pnpm dev` to check it.

## Troubleshooting

See [`docs/COMPONENTS.md`](docs/COMPONENTS.md#troubleshooting) for the
issues we've actually hit and fixed along the way: video flicker on clip
switch, blank slides from the double-buffered layout, `UnicodeEncodeError`

editors.
